# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev            # Vite dev server (PORT env var overrides the port)
npm run build          # tsc + vite build — this is also the type check
npm run ios:open       # build, cap sync, open Xcode
npm run android:open   # build, cap sync, open Android Studio
```

There is no linter and no test framework — `npm run build` (strict tsc) is the
only automated check. On this machine Java is not in PATH; run Gradle with
`JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`.

## What this app is

Focus On It: one screen, three text fields (Horizon / Now / Next step) plus a
hidden history panel. Deliberately minimal — no routing, no state library, no
backend dependency. The product tone is quiet; copy is phrased as gentle
questions, UI additions need a strong reason to exist. All code, comments, and
docs are in English (user directive — do not write Russian into the repo).

## Architecture

**Local-first state.** The entire app state is one small `FocusOnItState`
object (`src/types/index.ts`). `src/hooks/useStorage.ts` is the heart of the
app and the only place state logic lives:

- `normalize()` guards against garbage/old schemas on every load and import
- `rollOver()` implements the day rollover: a past day's "now" text moves into
  `history`, "now" resets for today. Called on load, on focus/visibility, and
  inside `setNow` — any change to rollover semantics must stay consistent
  across those call sites
- writes are debounced 500 ms, with a synchronous flush on
  `beforeunload`/`hidden`

**Dual persistence** (`src/utils/persist.ts`): localStorage is the fast
synchronous store; on device every write also goes to Capacitor Preferences
because iOS can clear WebView localStorage under storage pressure. Native
restore only fills an *empty* state, never overwrites typed text. The Supabase
session uses the same pattern (`src/auth/client.ts`).

**Auth is optional and lazily loaded.** Without `VITE_SUPABASE_*` keys in
`.env.local` auth is disabled: sign-in UI hidden, app runs fully local (this
is the v1 store configuration — see docs/PUBLISH.md for the keyless store
build). supabase-js is loaded via dynamic import behind `getClient()` in
`src/auth/client.ts` so it ships as a separate chunk that a keyless build
never fetches. Never import `@supabase/supabase-js` statically (types are
fine) — it would fold ~215 kB back into the main bundle. On device, OAuth runs
through the system browser + deep link `com.kartoshkin.focusonit://auth-callback`
(PKCE code handled in `AuthContext`'s `appUrlOpen` listener).

**Native shells.** Capacitor 8. iOS uses SPM, not CocoaPods (intentionally
absent on this machine). `cap sync` regenerates `ios/App/App/public` and
`android/app/src/main/assets/public` from `dist/` — never edit those copies.
On Android 15+ status-bar APIs are no-ops (edge-to-edge is forced); bar areas
are colored via `android:windowBackground` in `res/values*/colors.xml`, and
`src/native.ts` only paints the bar on Android < 15. The service worker
(`public/sw.js`) is web-only; native platforms skip registration.

**Icons/splash** are generated by `@capacitor/assets` from `assets/logo.svg`
+ `assets/logo-dark.svg` — regenerate with the flag set documented in
docs/ANDROID_PLAN.md (defaults produce a tiny logo on white).
