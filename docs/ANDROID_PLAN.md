# Focus On It — Android (Capacitor + Google Play)

> **Status (2026-07-19): Phases 1–3 done and smoke-tested on the API 36
> emulator** (light + dark, back button, minimize). Phase 4 is pre-wired:
> `app/build.gradle` picks up `android/keystore.properties` automatically once
> it exists — generating the keystore, and all of Phase 5, remain manual.
>
> One deviation from Phase 3 as written: on Android 15+ 
> `StatusBar.setOverlaysWebView`/`setBackgroundColor` are no-ops (edge-to-edge
> is system-enforced) and Capacitor 8 insets the WebView natively, so the bar
> areas showed the default white window background. Fixed deterministically:
> `android:windowBackground` is the paper color via `res/values/colors.xml` +
> `res/values-night/colors.xml`, and `initNative()` paints the bar paper only
> on Android < 15. Gradle needs Android Studio's JDK:
> `JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`.

## Context — how little there is to do

The app is already a cross-platform Capacitor project. Everything under `src/`
is platform-agnostic web code, and every plugin in use ships an Android
implementation:

| Plugin | Android backing | Notes |
|---|---|---|
| `@capacitor/app` | Activity lifecycle | deep links + back button |
| `@capacitor/browser` | Chrome Custom Tabs | OAuth (v1.1) |
| `@capacitor/preferences` | `SharedPreferences` | more durable than iOS WebView storage |
| `@capacitor/status-bar` | `WindowInsetsController` | theming works, behaves differently — see Phase 3 |

`env(safe-area-inset-*)` is already used throughout the CSS, so edge-to-edge
layout mostly just works. **No web code needs to change to get a running
Android build.** The work is: scaffold the platform, generate icons/splash,
one native-polish pass, then Play Store logistics.

Cost/friction vs. iOS: Play is a **$25 one-time** fee (vs. $99/year), and you
can install debug builds on any device with **zero signing setup** (unlike
iOS's 7-day free-provisioning dance).

---

## Prerequisites (one-time, manual)

1. **Android Studio** (latest stable) — bundles the SDK, an emulator, and the
   Gradle/JDK toolchain. Capacitor 8 needs **JDK 21**; Android Studio ships a
   compatible JDK, so no separate install is needed if you build from there.
2. First launch → SDK Manager → make sure the **Android 15 (API 35)** platform
   and build-tools are installed (Play requires new apps to target API 35).
3. A physical device (USB debugging on) *or* just use the bundled emulator.

## Phase 1 — add the Android platform

```bash
npm i @capacitor/android
npm run build            # produce dist/
npx cap add android      # scaffolds ./android (Gradle project) from dist/ + capacitor.config
```

`appId` is already `com.kartoshkin.focusonit` in `capacitor.config.ts`, so the
Android `applicationId` and package come out matching iOS automatically.

Add mirrored scripts to `package.json`:

```jsonc
"android:sync": "npm run build && cap sync android",
"android:open": "npm run android:sync && cap open android"
```

Then `npm run android:open` → Android Studio → pick an emulator or device → Run.
The app should launch identically to iOS.

**`.gitignore`**: `cap add android` writes a good `android/.gitignore`, but
double-check these are ignored (mirror of the iOS block): `android/app/build`,
`android/build`, `android/.gradle`, `android/local.properties`,
`android/app/src/main/assets/public` (regenerated by every sync, like the iOS
`public` folder), `android/app/capacitor.config.json`, and — critically — the
release keystore + `keystore.properties` (Phase 4).

## Phase 2 — icons & splash

`@capacitor/assets` is already a devDependency. It generates the full Android
resource set (legacy + adaptive icons, splash) from source images.

- Source icon: reuse the 512px maskable icon already in the repo
  (`public/icon-512-maskable.png`) — maskable art is exactly what Android
  adaptive icons want (safe zone in the center circle). Drop it at
  `assets/icon.png` (1024×1024 is ideal; upscale/re-export if needed).
- Optional splash: a `assets/splash.png` (2732×2732, logo centered on the
  `#F5F2EC` paper background) + a dark variant `assets/splash-dark.png`.

```bash
npx @capacitor/assets generate --android
```

This writes `mipmap-*/ic_launcher*` (foreground/background/adaptive) and
`drawable*/splash*`. Set the adaptive-icon background to the paper color
`#F5F2EC` so it reads as one calm tile.

**Splash screen plugin (optional but recommended):** Android has no storyboard
equivalent to iOS's launch screen. Without `@capacitor/splash-screen` you get a
brief themed blank screen. For parity install it and let assets generate the
resources:

```bash
npm i @capacitor/splash-screen
```

Configure a short, non-jarring splash in `capacitor.config.ts`
(`plugins.SplashScreen`: paper background, ~600ms, fade out). Keep it quiet —
in the spirit of the app, no spinner.

## Phase 3 — native polish (one pass)

Web layout already works; these are the Android-specific touches:

1. **Status bar / edge-to-edge.** `src/native.ts` calls `StatusBar.setStyle`,
   which works on Android too (it sets icon color). Android 15 *enforces*
   edge-to-edge, so also make the bar transparent and let the WebView draw
   behind it — the existing `env(safe-area-inset-top)` padding already reserves
   the space. Extend `initNative()` for Android:

   ```ts
   if (Capacitor.getPlatform() === 'android') {
     StatusBar.setOverlaysWebView({ overlay: true }).catch(() => {})
     StatusBar.setBackgroundColor({ color: '#00000000' }).catch(() => {})
   }
   ```

   Verify nothing tucks under the top status bar or the bottom
   gesture/navigation bar on a few screen sizes.

2. **Hardware back button.** Give Android its native gesture. With the History
   panel open, back should close the panel; on the root screen, back should
   background the app rather than do nothing. Add a listener (guarded to
   Android) using `@capacitor/app`'s `backButton` event — close History if
   open, else `CapApp.exitApp()` / `minimizeApp()`. Wire it wherever the
   History open/close state lives.

3. **Theme color.** Confirm dark mode (`prefers-color-scheme`) tracks the system
   theme on Android as it does on iOS — it should, since it's pure CSS.

## Phase 4 — signing & release build

Google Play distributes **AABs** (Android App Bundle), and uses **Play App
Signing**: you generate an *upload* key, Google holds the real app-signing key.

1. Generate an upload keystore (keep it OUT of git, back it up somewhere safe —
   losing it means you can't ship updates under your own upload key without a
   reset):

   ```bash
   keytool -genkey -v -keystore focusonit-upload.keystore \
     -alias focusonit -keyalg RSA -keysize 2048 -validity 10000
   ```

2. Store credentials in `android/keystore.properties` (gitignored):

   ```properties
   storeFile=../../focusonit-upload.keystore
   storePassword=…
   keyAlias=focusonit
   keyPassword=…
   ```

   and wire a `signingConfigs { release }` + `buildTypes.release` block in
   `android/app/build.gradle` that reads from it.

3. Set `versionCode` (integer, must increase every upload) and `versionName`
   (`"1.0.0"`, mirror `package.json`) in `android/app/build.gradle`. Confirm
   `targetSdk` = 35 (Play requirement for new apps).

4. Build the bundle:

   ```bash
   npm run android:sync
   # in android/:  ./gradlew bundleRelease   →  app/build/outputs/bundle/release/app-release.aab
   ```

   (Android Studio → Build → Generate Signed App Bundle works too.)

## Phase 5 — Google Play Console

1. **Register** a Play developer account — $25 one-time.
2. **Create app** → name **Focus On It**, default language, free, "App".
3. **Store listing:** short + full description (reuse the App Store copy — "A
   quiet place to see your horizon. Three slow questions a day — nothing
   else."), a 512×512 icon, a 1024×500 feature graphic, and ≥2 phone
   screenshots (grab from the emulator).
4. **Data safety form** (Play's analogue to App Privacy): for v1 declare **no
   data collected, no data shared** — the app is fully offline. Reuse the same
   privacy-policy URL as iOS (a public page must be linked even for "no data").
5. **Content rating:** fill the IARC questionnaire → expect the lowest rating.
6. **Testing → Production:** upload the `.aab` to an **internal testing** track
   first (instant, add your own email as a tester), sanity-check on a real
   device, then promote to Production. First review is typically a few hours to
   a couple of days.

The 4.2-minimum-functionality risk that looms over iOS web wrappers is far
milder on Play; the offline, native-storage nature of the app is an easy pass.

**v1 without auth:** the exact same `.env.local` gate as iOS applies — the store
build is produced from the keyless web build so no sign-in UI ships. Follow the
PUBLISH.md procedure (`mv .env.local .env.local.dev` → build/sync → restore)
before `bundleRelease`. One shared `dist/` feeds both platforms.

## Auth on Android (defer to v1.1, mirrors AUTH_PLAN.md)

The OAuth code path is already platform-neutral (`signInWithOAuth` +
`@capacitor/browser` + `appUrlOpen` deep-link handler in
`src/auth/AuthContext.tsx`). On Android `@capacitor/browser` uses Chrome Custom
Tabs — which Google accepts for OAuth just like iOS's SFSafariViewController.
Two Android-specific additions:

1. **Deep-link intent filter.** iOS declares the `com.kartoshkin.focusonit`
   scheme in `Info.plist`; Android needs the equivalent `<intent-filter>` in
   `android/app/src/main/AndroidManifest.xml` on the main activity:

   ```xml
   <intent-filter android:autoVerify="false">
     <action android:name="android.intent.action.VIEW" />
     <category android:name="android.intent.category.DEFAULT" />
     <category android:name="android.intent.category.BROWSABLE" />
     <data android:scheme="com.kartoshkin.focusonit" android:host="auth-callback" />
   </intent-filter>
   ```

   `appUrlOpen` then fires with the PKCE `code` exactly as on iOS — no JS
   changes.

2. **Google Cloud Console:** add an **Android OAuth client** (package
   `com.kartoshkin.focusonit` + the SHA-1 of both the debug key and the Play
   app-signing key — Play Console shows the latter under Setup → App signing).
   The existing **Web** client still drives the Supabase flow; the Android
   client covers the consent screen. **Sign in with Apple works on Android too**
   via Supabase's web redirect (Apple JS in the browser) — no native Apple SDK,
   nothing Android-specific beyond the deep link above.

Everything else in AUTH_PLAN.md (Supabase table, sync, account deletion) is
backend/web and shared across platforms unchanged.

## iOS → Android cheat-sheet

| Concern | iOS | Android |
|---|---|---|
| Platform folder | `ios/` (Xcode + SPM) | `android/` (Gradle) |
| Fee | $99 / year | $25 one-time |
| Local install | free provisioning, 7-day expiry | USB debug, no signing needed |
| Icon | `AppIcon.appiconset` | adaptive mipmaps (fg/bg) |
| Splash | LaunchScreen storyboard | SplashScreen API / plugin |
| Deep link | `CFBundleURLTypes` in Info.plist | `<intent-filter>` in Manifest |
| Store artifact | `.ipa` via Archive | `.aab` via `bundleRelease` |
| Signing | Apple manages certs | Play App Signing (upload key) |
| Privacy form | App Privacy → Data Not Collected | Data safety → No data collected |
